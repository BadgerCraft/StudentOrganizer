6. WHETHER PRIVATE STUDENT NOTES ARE ENCRYPTED
--------------------------------------------------------------------------------
Status: NOT CRYPTOGRAPHICALLY ENCRYPTED AT REST IN LOCAL INDEXEDDB.

Detailed Explanation:
Student notes in this local-first offline implementation are stored in the local
browser IndexedDB table studentNotes with the schema boolean flag isConfidential: true.
In the UI, notes are access-restricted, labeled with private lock badges, and excluded
from audit payloads and unencrypted CSV exports. However, cryptographic ciphertext
encryption (e.g. WebCrypto AES-GCM) is NOT currently executed on the raw string content
prior to local table storage.

--------------------------------------------------------------------------------
7. DETAILS REGARDING NOTES ENCRYPTION ARCHITECTURE
--------------------------------------------------------------------------------
- Current Implementation:
  Plaintext local storage in browser-isolated IndexedDB with logical access control
  and audit exclusions.
- Planned Implementation for Remote Cloud Synchronization:
  * Algorithm: AES-256-GCM authenticated encryption via standard browser WebCrypto API.
  * Location: Encryption immediately inside domain services prior to db.studentNotes.add()
    and decryption only within authorized UI components.
  * Key Management: A symmetric key derived via PBKDF2 (100,000 iterations, SHA-256)
    from a teacher-held secret passphrase or biometric credential, never transmitted to
    or stored on the server.
  * Lost Key Policy: Zero-knowledge recovery; if the passphrase is lost, encrypted
    historical notes cannot be recovered by administrators or the system.

--------------------------------------------------------------------------------
8. WHETHER OEN ENCRYPTION IS IMPLEMENTED OR ONLY REPRESENTED AS A SCHEMA FIELD
--------------------------------------------------------------------------------
Status: REPRESENTED AS A SCHEMA FIELD ONLY.

Detailed Explanation:
students.oenEncrypted is defined in src/types/schema.ts as string | null to
reserve the schema slot for future encrypted provincial Ontario Education Numbers.
Active cryptographic encryption of OEN is NOT implemented in this local build.
In accordance with strict student privacy guidelines, OENs are completely omitted
from seed data (oenEncrypted = null) and from all CSV exports and log outputs.
Instead, school-internal IDs are used via students.localStudentNumber.

9. DISCLOSURE OF INCOMPLETE, SIMULATED, OR STUBBED V4 REQUIREMENTS
--------------------------------------------------------------------------------
1. Cloud Gateway Synchronization (src/services/syncOutbox.ts):
   SIMULATED. The local queue writes idempotent syncMutations with client-generated
   mutationId, 	ransactionId, and sequence tracking. The worker simulates server
   push against an in-memory mock server ledger and updates local sync cursors.
   No live HTTP connection to a remote PostgreSQL / Supabase instance is active.

2. Dexie Schema Migrations:
   The database is currently at Version 1. Schema stores are established with full
   unique indexing. Migration logic between successive database versions is stubbed
   to execute when Version 2+ is declared in future iterations.

3. Device Installation Identity:
   Uses client-generated UUIDs stored in browser storage (dev-1, desktop-client)
   rather than hardware-bound TPM / MDM device certificates.

4. Real-time Multi-Device Conflict Resolution:
   Optimistic concurrency is implemented locally via ersion integer checking
   and ConcurrencyConflictError. Last-write-wins / three-way merge resolution with
   remote servers is deferred to cloud sync deployment.
