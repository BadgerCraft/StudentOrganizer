# Native streaming workspace archives

`electron/structuredWorkspaceArchive.cjs` is transport framing around the reviewed shared AEAD/chunk v1 objects. It does not modify those frozen crypto formats, grant access, configure a recovery key, publish a current root, or establish large-photo/device readiness.

## Main-only API

`exportWorkspaceArchive({workspace,root,scope,recoveryWrapper,sourceHead,key,write,assertCurrent,verifyRoot,cryptoRuntime?,purpose?,maxArchiveBytes?})` copies the native key and wipes its copy. The caller retains responsibility for wiping its own input key. `root` must be the exact OS-verified current checkpoint; `sourceHead` is `{revision,hash:SHA256(root.ciphertext)}`. `write(Uint8Array)` must provide backpressure into a private **ciphertext-only** staging destination. It must not publish a completed file before export resolves and the native file writer has durably finished. Failed or cancelled staging is not a backup.

`importWorkspaceArchive({read,getKey,createChunkStore,assertCurrent,verifyRoot,scope?,purpose?,expectedSourceHead?,cryptoRuntime?,chunkRuntime?,maxArchiveBytes?})` returns frozen `{root,scope,recoveryWrapper,sourceHead,archiveId,workspace}` only after complete authentication and graph closure. `read` yields byte pieces of at most 1 MiB (ordinary 64 KiB file streams fit). `getKey(header)` receives copied untrusted public header data and returns an **owned** native key; the helper copies and wipes that returned key, including cancellation. Recovery-code unwrap must use the header's exact app/vault/key version. No key, code, stream callback or storage factory crosses renderer IPC.

`createChunkStore(verifyManifest,assertCurrent)` has the same trusted factory contract as the structured engine. Import authenticates each ciphertext against the declared final seal’s expected hash and AEAD tag **before** staging it in shared immutable storage. A bounded one-ciphertext channel reuses the existing shared `verifyChunkStream` verifier; its verified sink stages the corresponding ciphertext and acknowledges it before the parser accepts the next chunk. Cancellation drains/rejects the verifier before wiping its key. It may publish verified immutable object manifests before the archive footer is known; it never commits a working checkpoint. Failed imports can leave orphan ciphertext. Existing objects are reusable only with exact descriptor identity and complete shared-stream verification; differing content is rejected. There is no silent overwrite, plaintext fallback, automatic retry, or garbage collection.

The returned workspace is a read-only preview whose own key copy must be released with `lock()`. Its checkpoint provider has no commit operation, and its temporary store verifier's key is wiped when import returns. Publishing an accepted import requires a separately opened native-owned session plus the normal confirmation, safety snapshot, identity, permission and protected-head protocol. A valid archive is not evidence that its source revision is newer than every other computer's state. `expectedSourceHead` can pin a particular expected source; otherwise old valid archives remain eligible for explicit manual preview. Cross-device adoption uses the explicit structured-engine import method after the native proof/confirmation flow: local heads remain fresh 1 or existing M+1, while the private root’s authenticated object-revision ceiling retains verified higher source refs. Ordinary restore cannot introduce a previously unknown future ceiling. This is not permission to reset or jump a local protected head.

`verifyRoot(openedReadOnlyWorkspace, checkpoint)` is a required main-owned callback for **each** reachable root. It must apply canonical application schema/bytes/ownership checks, including every dated historical snapshot, before claiming an authorized complete backup. A renderer boolean cannot replace it. The engine independently verifies cryptographic bodies and immutable ref bindings; it does not invent a class-access policy.

## Exact wire closure

The stream is bounded NDJSON, one compact JSON object plus newline per frame. Frame types are:

1. `header`: versioned native archive format, random archive ID, scope, `backup` or `transfer` purpose, authenticated creation time, current checkpoint, wrapped recovery key and source head.
2. Repeated `object`, sequential `chunk`, `object-end` groups containing the original shared-format descriptors, final seals and ciphertext chunks.
3. Exactly one `footer`, encrypted with the existing AEAD under the declared purpose and `archive/<random UUID>` context at the source revision.

The encrypted footer binds the exact header hash, byte-for-byte pre-footer stream hash, frame/object/root counts, source head and recovery-wrapper hash. Changing order, duplicating frames, changing scope/purpose, truncating even the terminal newline, adding trailing frames or substituting a wrapper fails verification. The recovery wrapper has the existing `recovery-key/master-key` context and must hash to the authenticated working root's wrapper hash.

`StructuredWorkspace.visitArchiveGraph` streams every body through the existing shared verifier while emitting ciphertext. It traverses current records, legacy dated JSON bodies and authenticated `internal-backup`/`internal-safety` root references. Immutable objects are deduplicated, while metadata ref hashes and logical identities remain checked. Reachable root refs must stay below their parent’s authenticated object-revision ceiling; nested root ceilings cannot exceed the top root’s known ceiling. A source clock can exceed the local computer’s root counter only after explicit verified archive adoption. Import reconstructs and verifies the complete graph, then requires exact equality between the objects present on the wire and those reachable from the root. Even a correctly encrypted footer cannot excuse missing or extraneous graph objects.

## Bounds and acceptance limits

Frames are at most 32 MiB. Aggregate archive input defaults to a **16 TiB planning ceiling**, which trusted callers can lower. This is not an actual disk/throughput/operating-system acceptance result. Imported descriptor metadata and graph traversal use 64 MiB raw metadata budgets; those are not JavaScript heap guarantees. Bodies are verified one shared 4 MiB chunk at a time and the helper never calls `readAll` or encodes a whole bundle. No whole plaintext temporary file is created.

The application still materializes primary data in memory. The 512 MiB `readAll`/`readSelected` preflight applies only to those APIs; native startup must use one `readSelected` call covering all materialized primary/control records while excluding lazy historical bodies. A loop that individually calls `readRecord` does not inherit that aggregate preflight. Per-record limits alone do not establish that bound. Root-control catalogs likewise need lazy bodies rather than retaining every ciphertext checkpoint string. Existing capture can represent a large archive together with originals, edits and base64 copies; such a primary workspace can exceed its materialization budget even though archive transport is streamed. Native `verifyRoot` may reject such a source until application validation/hydration is redesigned. Do not raise the 256 MiB record or 512 MiB aggregate read budgets silently, or label this helper as proof of large-photo readiness. Tests use synthetic modest bodies, injected bounds and real ciphertext SQLite staging; actual 100 GiB workloads, disk quotas, packaged Windows/Mac behavior, full real two-computer acceptance and user recovery-code acceptance remain unverified.

Focused tests include source clock 8 adopted at fresh local 1, subsequent local edits, restore of a retained source root, existing-profile import at local M+1, and rejection of unknown future roots. Focused tests also cover complete legacy/pinned/safety histories, exact historical strings, key ownership/wiping, truncated/reordered/duplicate/corrupt frames, scope/purpose/wrapper/source-head binding, graph omission despite a fixture-key-authenticated footer, size limits and context revocation. Independent source and test review is required before activation.

## Verified recovery lesson: authenticate before immutable staging

Ciphertext-only staging is not sufficient when the destination reuses immutable file IDs and chunk indexes. Review reproduced a corrupt archive placing a structurally valid but unauthenticated ciphertext into its genuine slot; the corrupt import failed, but a later intact retry hit the poisoned immutable slot. Existing immutable collision rejection was correct and must remain strict.

The repair authenticates the declared final-seal hash **and** AEAD before shared staging, using the existing shared verifier. An alternative architecture may stage in an isolated import namespace and promote only a completely verified graph, but must not overwrite or delete live immutable objects to recover from poisoning. Tests must retry the intact source in the **same** target store, rather than creating a clean directory that hides the failure.

The regression now exercises ciphertext-hash corruption, AEAD-tag failure with a fixture-authenticated hash commitment, a wrong seal, truncated valid prefixes, and a valid independently transformed chunk that disagrees with the declared seal. Each failed import is followed by two intact imports in the same target. A staging spy confirms rejected ciphertext is never inserted; correctly verified prefixes remain safely reusable. This is synthetic-data recovery evidence, not real-device acceptance.

The scoped retry guarantee addresses arbitrary corruption and alternate ciphertext that disagrees with the declared authenticated seal. A hostile holder of the raw master can forge authenticated app data, including a newly consistent seal and ciphertext under a reused immutable plan; this helper does not promise non-poisoning ingestion of such adversarial key-authorized archives. A stronger invariant would require isolated staging plus complete graph validation before promotion. Immutable collision refusal remains strict; never replace a live slot to accommodate a conflicting authenticated generation.
