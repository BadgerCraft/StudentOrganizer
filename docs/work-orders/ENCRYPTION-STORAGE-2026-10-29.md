## Recommended native integration

Keep the renderer's existing domain logic and atomic validation. An opt-in protected workspace can run in a named **nonpersistent Electron session** with HTTP cache disabled, hydrate only after main-process unlock, and use an encrypted authoritative container outside Chromium's ordinary persisted profile. The session must include classroom, recovery and content-bearing localStorage stores. This avoids exposing searchable plaintext indexes on disk, but requires a verified durable commit boundary: a save is not durable merely because a transient IndexedDB transaction completed. Do not enable conversion until every relevant write and attachment path has encrypted durable acknowledgement and failure/restart recovery coverage. Periodic snapshots over a persistent plaintext database are insufficient.

The native OS adapter should protect only per-app wrapping material through Electron safeStorage after app readiness, reject unavailable protection and Linux `basic_text`, and reject unsupported platform behavior. A synthetic test adapter is not proof of actual Windows DPAPI or Mac Keychain operation. Mac signing/Keychain continuity must be tested across supported installed updates. Separate app keys, purpose-derived subkeys, authenticated app/vault/object/version context and random nonces belong in the shared crypto contract; the storage adapter owns atomic file publication and revision checks.

Migration is a state machine: inspect → validate source snapshot → create encrypted candidate alongside preserved source → independently recover with the retained recovery code → verify second-device enrollment and round trip → explicit conversion confirmation → activate encrypted location. A failed or interrupted stage leaves the original usable and the candidate unactivated. Preserve legacy plaintext recovery deliberately and disclose its existence; no secure-deletion or retrospective-encryption claim. Once activated, failure to unlock or authenticate must block protected access, never select the old plaintext store as fallback. Rollback is explicit and must describe the restored revision, not silently select an older source.

## Reusable consumer requirements

Other authorized applications may use filesystem databases and large media rather than inline IndexedDB attachments. Reuse the reviewed crypto format and key lifecycle; do not assume the StudentOrganizer storage adapter applies. A large-media consumer needs bounded streaming/chunk authentication, object/sequence/final-length binding, truncation and reordering rejection, authenticated seek/range semantics for playback, and encrypted working journals/staging/safety copies. Existing backup-format limits must be preflighted; never substitute a plaintext transfer above an encryption bound. Consumer-specific private-source findings are retained in the coordinating task handoff rather than copied into this public repository.

## Acceptance and preservation checks

- Enumerate all content-bearing stores and attachments; test raw persisted artifacts for synthetic markers, including error/interruption residue and journals.
- Test wrong app, vault, object, purpose, version, key, recovery code, altered/truncated/reordered content and partial publication. Reject before domain restore or any replacement.
- Verify OS-unavailable and locked startup fail closed; no plaintext fallback and no retained unlocked renderer after lock.
- Verify recovery and second-device enrollment using independent synthetic device stores before exposing conversion activation.
- Inject failures before and after each durable boundary. Preserve the last acknowledged encrypted revision and untouched source; test explicit retry and stale-revision protection separately from rollback.
- Preserve class/session/teacher boundaries, source bytes, grades, exact level conversions, reports and audit/outbox relationships after authenticated round trips.
- Verify existing plaintext exports are clearly identified and never masquerade as encrypted backups/transfers. Do not promise OS-level secure deletion, memory/swap protection or protection while unlocked.
