## End-to-end evidence

Packaged window disables Node integration, enables isolation/sandbox/webSecurity (`main.cjs:64-70`). Navigation/new windows and requests outside bundled files/data/blob are denied (`main.cjs:97-126`). Build-time CSP (`vite.config.ts:8-17`) prevents renderer connections and script/object injection. Development Vite does not carry the packaged resource contract; browser previews are not evidence of native IPC enforcement.
2. **Drive connect → verified download → local matching.** The optional operator-owned config never enters IPC. `electron/captureDriveAuth.cjs:17-54` uses fresh random state/PKCE, random loopback port, host/path/method/state validation, bounded token exchange, exact file-only scope and no retained refresh token. `electron/captureDrive.cjs:29-49` serializes operations, bounds time, aborts cancellation, keeps access in memory and prevents arbitrary URLs/redirects. `captureDrive.cjs:99-115` requires an ID from the prior list, verifies owner/private folder and file, hashes actual bytes and rechecks metadata/account after download. `src/capture/DriveCapturePicker.tsx:22-34,59-66` aborts/disconnects on unmount, invalidates late results and delivers a `File` to the existing local importer, not database writes. No background retries, uploads or deletion in this desktop path.
3. **Feedback → dictation → explicit insertion.** `src/dictation/session.ts:14-54` ties token/capture/transcript to one generation and discards late work; `DictationFeedback.tsx:21-39,48-58` keys the session to the feedback target, clears transcript on interruption/disable, preserves existing text and requires explicit insertion before normal Save. `audio.ts:3-42` stops tracks, bounds recording size/duration and emits PCM. `electron/dictationIpc.cjs:24-55` requires per-recording consent and owning main-frame audio permission. `dictation.cjs:7-12,56-80` validates WAV bytes and passes only bounded stdin to fixed executable arguments with shell disabled, no file-output flags, bounded inference/output and cancellation. Native runtime provenance/signing verification lives in packaging hooks and `scripts/dictationRuntimeIntegrity.cjs`, not renderer-controlled installation.
4. **Update → exact artifact → recovery-first install.** `electron/releaseDelivery.cjs:43-65,105-124` binds repository release, approval, architecture, artifact size/hash, publisher policy and resolved Git tag source. `windowsInstallerUpdate.cjs:174-197` disables startup downloading/quit install, strips identifying headers and restricts feed. Download verifies bytes/signature; installation first validates/writes/readbacks complete backup, rechecks bytes/signature and writability, then launches (`:198-274`). Launch interception deliberately waits for OS process creation and rejects elevation/helper fallback before quitting (`:111-165`). This is substantially stronger than a renderer-selected URL or automatic install-on-quit model.
5. **Report → private PDF → atomic replacement.** `electron/reportPdf.cjs:8-38` validates request size/name, creates scriptless sandboxed renderer in an ephemeral session with data-only requests, validates generated PDF, writes private same-directory staging and readbacks before rename. Cleanup does not turn completed replacement into reported failure. `src/services/reportPdf.test.ts:48-84` exercises actual temporary filesystem preservation under generation/write/validation/replacement failure, with mocked browser renderer.

## Justified maintenance improvements (not current defects)

- **One versioned backup contract across runtimes.** Native validator hardcodes all 41 tables and schema5 at `electron/windowsInstallerUpdate.cjs:10-24`; exporter and migration validator separately define schema at `src/services/portabilityService.ts:805-853`; exact pretty-print capacity calculation repeats the envelope in `src/capture/backupCapacity.ts:12-15`. Present values align, and `windowsInstallerUpdate.test.ts:269` guards the capture/native byte ceiling. A future schema/table change can leave auto-update unable to accept the app's own valid backup. Share a runtime-neutral manifest/version contract and test real exporter → native validator compatibility after every schema migration. Do not weaken whole-backup validation or infer a current failure from duplication.
- **Treat updater internals as a pinned integration contract.** `windowsInstallerUpdate.cjs:127-163` overrides `spawnLog`, invokes `install`, resets `quitAndInstallCalled` and accesses `updater.app`; `:185-194` overrides header/HTTP internals. This protects real recovery behavior but increases dependency-upgrade regression risk. Retain the narrow adapter and exact-version pin; require actual installed NSIS replacement/failure/bootstrap tests on updater upgrades. No rewrite warranted, and replacing it with default quit-before-launch would lose an intentional safety invariant.
- **Keep mock sync visibly outside the production transport boundary.** `src/services/syncOutbox.ts:98-117` acknowledges records after adding IDs only to a process-local mock ledger; `:172-186` inbound student method has no real server authentication/version contract. Repository reference search found no production caller, only tests/benchmarks. Therefore this is not a reachable remote authorization finding and does not establish working server sync. Move/name the simulation explicitly as test support when sync next changes; require a separate authenticated, atomic inbound/outbound design before exposing it. Avoid deleting audit/outbox data or treating this as authorization for live sync.
