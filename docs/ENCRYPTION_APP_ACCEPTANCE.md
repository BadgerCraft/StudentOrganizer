## Using the staged workflows

This build leaves real activation disabled. Normal existing work is still in the original workspace until a separately accepted native setup and explicit conversion. The following describes the implemented review/test workflow, not permission to provision a user's devices.

- Settings → Protection prepares an offline recovery code and a second-computer check. Verify both actual proofs; completed steps collapse into summaries and can be reviewed. Keep the code offline, separate from encrypted copies, and out of bug reports or AI chats.
- Conversion retains the original source and opens the encrypted copy in a fresh protected window. Subsequent work belongs to that encrypted copy; the original can become stale. No source deletion or secure erasure is performed.
- Backups remain in Settings. Native encrypted export includes reachable dated and safety history plus its encrypted recovery-key wrapper. A file alone is insufficient without a usable trusted-device key or the matching recovery code. Keep a verified copy separately.
- A previously unenrolled computer can recover from a complete encrypted archive and code even when the original computer is unavailable. Preview, select the archive profile, explicitly preserve the local original source, then confirm. Preview/cancellation does not replace the working revision. Existing protected heads, unknown registrations and uncertain states are refused; recovery is not a head-reset command.
- If initial conversion stops after a verified empty enrollment but before revision1, the explicit original-source return permits preparation again. The retained protected master is reused; a newly verified recovery code and new second-device challenge are required, and the old response is rejected. Older codes/copies are not securely erased or cryptographically revoked by this retry.
- After an uncertain write or restore, reopen secure startup and inspect its verified saved revision before retrying. Pending edits are not automatically replayed. Keep the original and encrypted recovery copies when an error says registration or key access cannot be verified.
- Personal Drive remains optional and off until actual setup and two-computer acceptance. Its existing100MiB primary-snapshot limit is preserved; encrypted file archives handle separate full-history copies. No live account or permissions were configured in this work.

Readable PDF/CSV outputs remain blocked in protected mode pending Tyler's explicit export-policy choice. Legacy exports retain their existing behavior. Physical-device usability, actual Mac Keychain access, live Drive and abrupt power-loss behavior are not established by synthetic tests. Lost/unverifiable established registration/head repair is a separate boundary; never delete keys or metadata to force a fresh setup.
