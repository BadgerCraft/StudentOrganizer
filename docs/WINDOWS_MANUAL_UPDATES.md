### Implemented behavior

Settings: Check for updates -> Download update with progress/cancellation -> Backup and install -> Install and reopen. The last action requires saved Settings and no pending Settings write/editor. It creates the existing complete transaction-consistent JSON backup and runs the recovery validator; the main process validates all39 tables, writes/syncs/renames a private local backup in `userData/update-backups`, then reads back exact bytes before launching replacement. No classroom records leave the device. Backups are not app-encrypted and remain subject to OS profile access and any device backup software.

The pinned `electron-updater`6.8.9 standard NSIS updater handles download/hash/replacement. The main process owns a fixed public BadgerCraft/StudentOrganizer GitHub provider; stable expected-version/architecture NSIS filename and SHA512 metadata are mandatory, while web installers, prereleases, downgrades, arbitrary URLs/paths and staged rollouts are rejected. The downloaded bytes and Windows Authenticode status are rechecked after the backup before execution. Invalid signatures stop installation. Current unsigned installers need a separate unchecked-by-default acknowledgement in the install confirmation. Download checksums protect integrity against the selected metadata; they do not establish publisher identity or protect against compromise of the release repository. No paid signing or invented trusted publisher is configured; unsigned public distribution remains held for a separate decision.

Renderer networking remains denied by CSP/session policy. A separate updater network session permits only HTTPS requests to the fixed repository/release-assets hosts and strips cookies, authorization/referrer/staging/device headers. The library's default persistent rollout identifier is disabled. Only fixed update request headers are sent; GitHub still sees connection IP and requested versions/assets. No startup request or timer-triggered network operation is introduced. Local status polling only reads controller state. Portable/unpacked/non-Windows copies cannot run installer replacement, though Windows packaged copies can check metadata.

App identity and normal `userData` remain stable. A single-instance lock prevents a second copy from writing during replacement. Cancelled/failed downloads are cleaned and retryable; metadata/download have total deadlines. A launch failure must be surfaced before quitting rather than claiming an install started. Once Windows actually begins replacing binaries, OS/UAC refusal, shutdown or interruption still needs its own acceptance evidence and recovery; no atomic binary rollback is promised. The verified local backup remains available for normal UI recovery after repair/reinstall. Existing copies need one deliberate installation of the updater-enabled version before they can use it; old metadata-only builds cannot install their own first updater.

## Installation remains blocked

GitHub release metadata is not a signed installer manifest. A repository URL or an artifact hash obtained from the same unsigned source is insufficient installation authorization. No trusted signed manifest/public verification key, expected Windows publisher identity, approved stable installer channel or actual old-to-new signed installer acceptance has been established. Accordingly no executable URL is exposed, downloaded, opened or run. The available-version message explicitly says installation is unavailable until source/signature verification is established.

The existing app identity (`ca.on.teacher.assessment`, `ontario-teacher-assessment`), `userData` location, database version/schema and restore behavior remain unchanged. This patch does not prove installation-over-existing-records preservation: that requires an approved authentic old/new pair on Windows, a fictional database and backup, and restart/record-count/recovery checks. Portable and installed paths must be tested separately. Do not publish an unsigned release to work around this blocker.
